### 도영 님 지시 (원문)
> 시스템 파트랑 ui 파트 담당자들도 지금 진행하는 각 프로젝트에 필요한 내용들 질의 받고 가능한 모든 파일들은 공개하고 해당 파일이 어떤식으로 구현되어야 좋은지 스토리 파트도 함께 질의해서 지금부터는 각 파트간의 유기적인 프로젝트 착수를 진행해. 오전 7시까지 잘 예정이라 인터뷰나 컨펌은 어렵기에 어느정도 데모파일로써의 게임 개발에 나가고 싶은 것이니 현재까지 얘기한 부분들을 기반으로 너가 생각하기에 권장하는 부분들로 결정해서 계속 진행해줘. 나는 지금부터 응답 어려워 작업 병행해서 진행해.

### 정리
1. **파트 간 참조 전체 공개**: 모든 파트가 모든 파일을 읽을 수 있다 (`cross-references.md` #5). 쓰기는 여전히 자기 소유 경로만. 파트 간 필요 사항은 메인 세션(프로듀서)이 질의·전달한다.
2. **스토리 파트 자문**: 시스템·UI·아트가 만드는 파일의 구현 방향(이름·문장·분위기)을 스토리 파트에 질의해 반영한다.
3. **자율 결정**: 도영 님 부재(오전 7시까지) 동안 선택 사항은 Claude 가 **권장안**으로 정하고 진행한다. 모든 자율 결정은 이 로그 아래 "자율 결정 목록"에 적어 복귀 후 검토받는다. 되돌리기 쉬운 형태(데이터·문서)로 둔다.
4. **목표**: 데모 빌드 — 아트(주인공·1층 타일·적·무기) 적용, 27라운드 시스템 반영, UI 메뉴·표시, 스토리 문장 확장. 가능하면 음향 1차.
5. 인터뷰 원칙(루트 CLAUDE.md 1장)은 이 라운드 동안 "권장안 자동 선택 + 기록"으로 대체. 도영 님 복귀 시 원복.

### C. 시스템 스프라이트 연동 임시값 (시스템 파트, 복귀 후 검토)
- 서빙 경로: `assets/**` → `assets-game/**` (해시 번들 `dist/assets/` 와 충돌 회피). dev 미들웨어 + build 복사, `manifest.json` 으로 존재 파일만 로드(404 없음). `@types/node` devDependency 추가.
- 방향 규칙: 정지·공격은 **마우스 조준 방향**, 이동 중은 **이동 방향**. 방향 전환 시 걷기 프레임 이어가기.
- 공격 애니 길이 = 무기 `cooldownMs` 에 맞춤(단검 빠르게, 대검 느리게). 대쉬 애니 = 대쉬 `durationMs`.
- 피격 2프레임 뒤 복귀, 사망은 끝 프레임 유지 후 `+400ms` 에 결과 화면. 적 시체 0.5초 유지 → 0.6초 페이드.
- 그림자: 검정 타원, 알파 0.35, 폭 = 바디 폭 + 2, 높이 비율 0.4. 시트가 있는 개체만.
- 바디: 플레이어 12×12(data) 유지, 발밑 정렬(가로 중앙, 아래 끝 = 피벗 행). 적은 `data/enemies.json` size 그대로 발밑 정렬. 깊이 = 발 y.
- 시트 모드의 상태 표시: 패링·가드·조준·후딜은 기존 색을 **곱 틴트**로, 대쉬는 애니만. 경직·예고도 틴트. 피격·패링 번쩍임은 전체 채움 틴트.
- 소품 배치: 방당 2~5개, 문 주변 체비셰프 2칸·시작 지점 2칸·보스 방 중심 (좌2·우5·상2·하2) 제외, 단단한 소품은 벽가 테두리만, 소품 레이어는 바닥 위 오버레이(깊이 0.5, 개체 아래 — 개체가 소품 앞에 겹칠 때의 가림은 미구현).
- 벽 자동타일: 아래 칸이 열려 있으면 `top`(벽돌 정면), 그 외 `bottom/left/right/corner_*`, 아무것도 아니면 단일 벽.
- 팔레트 스왑은 `data/palette.json`(아트 팔레트 사본) 기준, 캐릭터 시트 전부(플레이어·적·보스)에 적용. 타일셋은 층별 파일이므로 치환 없음(2층 이후 타일셋 미제공 → 플레이스홀더).
- 사수 발사 타이밍을 attack 2번째 프레임(첫 프레임 160ms 뒤)에 맞춤(아트 제안 수용).
