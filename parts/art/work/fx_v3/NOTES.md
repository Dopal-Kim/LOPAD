## 1. 배율 판단 (중요)

- 구 fx 는 `pixelScale` 없음 = **2**(계약 §9 "기존 도트 = 없음/2, 시스템이 2배로 그림", §11 "v1 = 2"). 구 hit_burst 24도트 = 화면 48 논리 px.
- v3 = `pixelScale 0.5`. 같은 화면 크기를 지키려면 **도트 ×4**(24 → 96). 지시문의 "2배 밀도"는 v2(=1) 기준으로 읽었다(주인공도 구 16×24 → v3 64×96 이 ×4). §11 문구 "이펙트 v3: 기존 크기 ×2" 는 이 해석과 어긋나므로 계약 문구 정정이 필요(아래 3절 초안).
- 예외: 주인공에 붙는 `dash_trail`(주인공 실루엣)·`dash_dust`(주인공 발) 는 53라운드 Q1 주인공 1.5배에 맞춰 **×6**. 나머지는 ×4(적 크기는 후속 결정이라 그대로).
- 길이 필드(도트 단위)도 같은 배율: `pivot`, `boss_slam.hitRadiusPx` 40 → 160, `soul_wisp.drift.pxPerSec` 6 → 24, `telegraph_line` 타일 주기 16 → 64(`tilePeriodPx`). `scale`(판정 반경 / 기준 반경)은 비율이라 그대로이고, `shake.px`(카메라)도 그대로다. 구 값은 각 JSON `legacy` 에 남겼다.
- 판정·타이밍(프레임 수·`frameDurationsMs`·`loop`·`anchor`·`spawn`·`segments`·`progressDriven`·`directions`)은 구 시트와 같다. build 에서 프레임 수를 assert 한다.

## 3. 계약 문구 초안 (§11 에 추가)

> - **이펙트 v3**: `sprites/fx/v3/<이름>.png/.json`, `pixelScale: 0.5`. 우선순위는 다른 분류와 같다(v3 → v2 → 구). 시트 단위로 대체한다(같은 이름의 v3 가 있으면 v3, 없으면 구 시트).
> - 크기: 구 fx(pixelScale 2)와 **화면 크기가 같게 도트 ×4**. 단 주인공에 붙는 `dash_trail`·`dash_dust` 는 주인공 v3(1.5배)에 맞춰 ×6. ("기존 크기 ×2" 문구는 이것으로 바꾼다.)
> - 프레임 수·ms·loop·anchor·spawn·segments·directions 는 구 시트와 같다. 도트 단위 길이 필드(pivot·hitRadiusPx·drift.pxPerSec·tilePeriodPx)는 시트 도트로 적고 시스템이 pixelScale 로 환산한다. `scale`(비율)·`shake.px`(카메라 논리 px)는 환산하지 않는다. 구 값은 JSON `legacy` 에 참고로 남는다.
> - `telegraph_line` 은 TileSprite 주기 64 도트(`tilePeriodPx`) — 타일 폭 = 사거리(논리) / pixelScale.

## 4. 그리기 방식 (단순 확대 없음)

- 모든 모양을 v3 해상도에서 곡선으로 새로 그렸다. `fxkit` 는 곡선을 촘촘히 나눠 **끝이 뾰족해지는 캡슐 사슬**로 칠한다(점에서 선분까지 거리 정확 계산, 폭·밝기를 선을 따라 보간). 레이어 안은 최댓값으로 합쳐 겹친 획이 하나로 녹고, 획 한가운데가 가장 밝은 1px 심이 된다. 값은 레이어 램프(어둠 → 밝음)로 양자화한다.
- 획 끝: 광선·불티·혓바닥·물방울 꼬리·점선 토막이 모두 끝이 바늘처럼 모인다(51라운드 획 피드백). 점선 토막도 양끝이 뾰족하다.
- 색: 불티·광선은 층 램프(1층 호박) → X1 → X0, 먼지·재는 주인공 재 램프(따뜻한 회색), 피는 층 램프의 어두운 쪽(호박빛 진액).

## 5. 자기 비평 (see → critique → fix)

### 1회차 (구 시트와 나란히 2배 비교)
1. 타격 첫 프레임이 구보다 훨씬 작고 약함(hit_burst f0 코어 지름 13 vs 구 환산 약 40) → hit_burst f0 코어 r6.5 → 10.5, 십자 바늘 17 → 28, crit_burst f0 r10 → 15, boss_slam f0 r22 → 34, telegraph_aura 코어 r9 → 17.
2. 먼지(대쉬·넉백·보스 슬램·사람 피격)가 둥글고 어두운 테두리 때문에 '돌멩이'로 읽힘 → 먼지 램프를 밝은 재 회색으로, 덩이를 3잎 구름(`cloud`)으로, 피격 먼지는 윗면 호만.
3. 예고 띠가 구보다 가늘어 판정 판독이 약함 → 링 반폭 2.8 → 4.2, 부채꼴 변 2.4 → 3.4, 선 4.6 → 6.4.
4. 불바다가 혓바닥이 떨어진 '촛불 줄'로 읽힘 → 웅덩이를 따라 이어진 불 바닥 띠 + 혓바닥 9 → 15(겹침, 뒤에서 앞 순서).
5. 대쉬 잔상 줄무늬가 모든 방향 가로줄 → 이동 방향을 따르는 줄(좌우 = 가로, 상하 = 세로), 마지막 프레임은 무작위 점 대신 줄 토막.
6. 피 f1 이 중심에서 부챗살처럼 펼쳐짐 → 꼬리 길이 줄이고 시작점을 띄움, f0 덩이 키움, 물방울 밝기 한 단 낮춤.

### 2회차 (새 시트만 2배)
1. 대쉬·넉백 먼지 위 알갱이(어두운 재)가 구름 위에 찍혀 지저분 → 알갱이 레이어를 구름 아래로.
2. 불 혓바닥 높이·기울기가 고르게 반복 → 높이 0.55~1.05 범위, 혓바닥마다 기울기·흔들림 폭 다르게.
3. 혼불 머리가 길쭉한 촛불 모양·16색 → 몸 넓고 둥글게(끝 짧게), 꼬리·심·바닥 고리 색 줄여 11색.

### 3회차 (확대 픽셀 검사 + 1배 목업)
1. 예고 링 안에 계단 줄무늬(값 양자화 띠가 1px 씩 번갈아 생김) + 점 도장 방식의 잔물결 → 그리기 도구를 '점 도장'에서 '선분 거리 정확 계산'으로 교체, 예고 띠는 테두리 / 평평한 몸 / 1px 심 3단 램프(`tel_ramp`, 진행도마다 몸·심 색만 밝아짐).
2. 보스 슬램·탄생 흩어짐 먼지 덩이가 여전히 '자갈 고리' → 낮은 대비 재 램프 + 납작하게, 슬램 먼지는 22 → 34덩이로 이어진 띠.
3. 1배 목업에서 대쉬 먼지가 커진 주인공 발밑에서 작은 돌처럼 보임 → 주인공 1.5배에 맞춰 ×6, 발에서 뒤로 작아지는 구름 4개 + 상하 대쉬는 V 자로 벌어짐, 구름 가장자리 체크 무늬 1줄로 부드럽게.

## 6. 남은 약점

1. 먼지 구름은 불투명 도트라 1배에서 여전히 단단해 보인다(반투명 0 원칙). 시스템이 알파 페이드를 쓰면 나아진다.
2. 피는 1층 호박 램프 어두운 쪽이라 어두운 바닥에서 작고 흐리다(구도 비슷). 적 크기 조정 때 함께 키울지 재검토.
3. `telegraph_line` 은 2프레임에 반 주기(32) 이동이라 흐름 방향이 모호하다(구 시트도 같음). 방향을 보이려면 3~4프레임이 필요(타이밍 변경 → 질문).
4. `dash_trail` 은 현재 `player/v3/player_dash` 2프레임의 사본이다. 주인공 대쉬 그림이 바뀌면 `build.py dash_trail` 재빌드 필요.
5. `birth_dust` 는 v3 탄생 몸 시트에도 재 소용돌이(44알)가 있어 겹쳐 보면 알갱이가 많다 — 게임에서 함께 확인 필요.
6. 보스 슬램 균열은 매 빌드 같은 모양(seed 고정) — 여러 번 찍어도 같은 균열.
